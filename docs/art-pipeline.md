# 의류 그림을 추가하는 방식

사용 중 이미지 생성 API를 호출하지 않는다. 그림은 제작 단계에서 생성·검수하고 정적 파일로 배포한다. 포즈를 추가할 때는 별도의 등록 프레임을 만든다.

## 현재 기준

- 화면·이미지 공유는 `composeLayers()`의 같은 조합 결과를 사용한다.
- 모든 부위는 400 × 600 기준 좌표를 사용한다. 남녀 부위의 좌표를 공유하지 않는다.
- `catalog-front.json`은 원본 이미지 영역과 실제 착용 위치를 구분한다. 상품 썸네일의 위치를 착용 위치로 쓰지 않는다.
- `attachment-rules.js`는 후드 노출 범위·패딩 깃 가림·모자 아래 머리카락 가림을 정의한다.
- 후드는 독립적으로 생성한 목깃을 붙이지 않고 원래 후디의 등록된 그림을 사용한다. 바로 아래 후디만 노출한다. 다른 상의 속의 후드는 바깥으로 통과시키지 않는다.
- 모자는 정면 전용 그림을 사용하고 머리 위쪽을 먼저 가린 뒤 그린다. 현재 정면 포즈에서는 하나의 앞쪽 모자와 머리 가림으로 충분하다. 옆 포즈·복잡한 머리에는 뒤/앞 모자를 별도 그림으로 등록해야 한다.
- 발열 하의는 전용 타이츠 그림을 사용한다. 일반 바지 안에서는 가리고 겹 검사에서만 드러낸다.

## 추가·변경 절차

1. 기존 기준 포즈를 참고해서 새 그림을 제작한다. 목·어깨·손·허리·발목 기준점과 가려질 부분을 함께 지정한다.
2. 투명 영역과 앞/뒤 부위를 확인한다. 머리와 의류가 함께 생성된 그림은 임의로 다른 포즈에 올리지 않는다.
3. 카탈로그에 원본 영역·착용 위치·썸네일을 등록한다. 이미지가 찌그러지지 않도록 종횡비를 유지한다.
4. `npm test`로 등록 범위·겹 순서·가림 규칙을 검사한다.
5. `npm run art:review` 실행 후 개발 서버의 `/art-review.html`에서 대표 32개 조합을 육안 검수한다. 목선, 후드, 모자와 눈, 손, 긴 안쪽 옷자락, 내복, 신발을 확인한다.
6. 실제 옷장에서 색 변경·순서 변경·벗기기와 공유 이미지를 확인한다. 검수되지 않은 새 자산은 공개 옷장에 추가하지 않는다.

자동 검사가 통과해도 자연스러운 그림이라는 보장은 없다. 형태가 크게 맞물리는 새로운 조합은 전용 결합 그림을 제작하거나 앞/뒤 파츠를 분리해 등록한다. 실시간 생성은 매번 결과가 달라져 이 검수를 대신하지 못한다.

## v8 제작 기록

내장 이미지 생성 도구로 `registered-accessories-v8.png`를 제작했다. 프롬프트: 기존 연필선·종이 질감에 맞춘 투명 3 × 2 의류 시트. 남녀 정면의 차콜 발열 타이츠(밴드·발목 시보리, 단추·벨트 고리·지퍼 없음), 정면 버건디 볼캡 2종, 정면 올리브 비니 2종. 몸·얼굴·발·글자 없이 각 셀에 완전한 의류를 배치한다. 원본은 보존하고 카탈로그의 영역 지정으로 사용한다.
